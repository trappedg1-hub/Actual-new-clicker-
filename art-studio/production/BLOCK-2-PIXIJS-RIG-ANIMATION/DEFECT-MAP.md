# КАРТА ДЕФЕКТОВ — диагностика чёрных разрывов (2026-11-12)

Мандат: каждый видимый дефект классифицирован по источнику, без смешивания
причин. Категории:

- **A** — дефект уже запечён в approved PNG слоя;
- **B** — неправильная нарезка альфа-маской на этапе runtime;
- **C** — шов между независимыми слоями;
- **D** — движение/поворот/деформация раскрывает контур;
- **E** — PixiJS: загрузка текстуры / premultiplied alpha / сэмплирование /
  композитинг.

Критерий всех измерений — итоговое изображение (композит всего рига),
снятое в 16 фазах дыхательного цикла (шаг 250 мс) + 16 последовательных
кадров с шагом 16 мс. Сырые данные: `qa-animation/final-verify/` (workspace).

**Доказательство для двух крупнейших компонент (hair_back_01):**
в approved-оригинале `art-studio/references/originals/IMG_4038_rig-pose.webp`

вырезали НАРИСОВАННЫЙ арт, ошибочно приняв тень за фон.

**Исправление (без изменения единого approved-файла):** runtime-модуль
`src/heroine/rig/alphaRepair.ts` — перед загрузкой текстуры в GPU замкнутые
внутренние компоненты ≤1500 px становятся непрозрачными; RGB полностью
прозрачных пикселей восстанавливается 1:1 из approved-оригинала IMG_4038
по тем же координатам холста (точные пиксели художника, не генерация, не
blur). Компоненты >1500 px и помеченные художественные просветы
(`approvedOpenings`, z17) не трогаются. Проверка: средний RGB
восстановленных пикселей в runtime == среднему RGB оригинала байт-в-байт
(L: 58.6/36.0/75.0; R: 58.7/34.8/74.2), альфа 255.

## Категория B — нарезка альфа-маской в runtime: ИСКЛЮЧЕНА

Runtime не режет слои маской. Проверено побайтовым сравнением runtime-слота
(считан обратно из подготовленного буфера текстуры) с approved PNG для
z01, z05, z08, z12: **0** расхождений альфы вне отремонтированных пикселей,
**0** расхождений RGB на непрозрачных пикселях. Отличия = ровно
инвентаризованные дыры категории A (z01: 1430, z08: 872, z05: 10, z12: 83).

## Категория C — швы между слоями: сведены к слабым AA-швам

После заваривания движения (см. D) в композите не осталось ни одного
полностью прозрачного пикселя внутри силуэта ни в одной из 16 фаз.
Остаточные швы — только полупрозрачность AA-контуров разреза (1px):

- (497,253)-(525,305) и (513,240)-(519,253) арт-координаты: стык
  hair_side_r / воротник;
- (353,304)-(359,310): стык воротник / плечо слева;
- (263,375)-(268,383): контур левого рукава (виден на выдохе).

Минимальная альфа 182–191, средняя ~215 (просвет фона ≤25% в линии 1px
толщиной), значения стабильны по всем фазам. Чёрных щелей (альфа≈0),
которые были причиной жалоб, в композите нет: `interior_report.json` —
570±6 px слабой альфы, min_alpha 191 во всех 16 фазах.

## Категория D — движение/деформация: устранена заваркой в общее поле

Измерено по 16 фазам + 16 последовательным кадрам (шаг 16 мс):
количество и позиции внутренних непрозрачностей композита НЕ зависят от
фазы (570±6 px, одинаковые компоненты) ⇒ движение больше ничего не рвёт.

Исправления (замеры «до» — в коде комментариями у каждого параметра):

- маятники убраны, их слоты переведены в общее дыхательное поле
  (`BREATH_MESH_SLOTS` = {1,2,5,6,7,8,9,10,11,12}): задние пряди, обе руки,
  обе части юбки деформируются теми же строками, что и торс — контур
  разреза между любыми двумя слотами смещается одинаково;
- `MOTION.hairSwayPx/hairLagPx/armGroupRotationDeg/armSlotRotationDeg/`
  `hairGroupRotationDeg/hairSlotRotationDeg/skirtRotationDeg` = 0,
  `LEG_POSE.rotationDeg` = 0 (поворот бедра открывал щели юбка↔бедро);
- боковые пряди (z17, z18) перевешены в головную группу (сварены с головой
  и воротником);
- движение осталось: дыхательное поле (liftPx 8) деформирует весь корпус,
  ноги — позовый warp 28px у колена, чёлка — вторичное качание поверх
  непрозрачной головы, реакции на касания, моргание/рот.

## Категория E — PixiJS-конвейер: ИСКЛЮЧЕНА

Декод `createImageBitmap(premultiplyAlpha:"none",
colorSpaceConversion:"none")` + чтение через WebGL-фреймбуфер с
`UNPACK_PREMULTIPLY_ALPHA_WEBGL=false`; текстуры `no-premultiply-alpha`;
побайтовая проверка B подтверждает тракт целиком (PNG → буфер → GPU →
readback без изменений). Канвас-путь остаётся только как fallback для
браузеров без createImageBitmap.

## Что сделано фактически / что требует разрешения

**Исправлено без изменения approved-файлов:** все перечисленные дефекты
категорий A (runtime-восстановление из approved-оригинала), C, D.
B и E дефектов не содержали (исключены измерениями).

**Требует отдельного разрешения (опционально):** постоянная запечка
исправлений категории A в сами PNG слоёв (вместо runtime-восстановления).
Файлы: все 20 слоёв `BUILD-v01/layers/*.png` (главные:
01_hair_back_01, 08_outfit_blouse, 20_hair_front_02, 17_hair_side_l,
06_arm_l). План: тот же алгоритм (замыкание внутренних компонент +
RGB из IMG_4038), один раз оффлайн, с попиксельным отчётом CHANGED-PIXELS.
Без разрешения файлы не тронуты — текущий runtime-ремонт полностью
закрывает дефекты на экране.
