## 1. Почему в запросе указан HEAD `d17af3e` — проверка

**Коротко: в git это не так.** И локально, и на GitHub текущий HEAD ветки — `798f884`.
`d17af3e` существует, но это **предок на два коммита назад**, коммит E1.

| Проверка | Результат |
|---|---|
| `git rev-parse HEAD` | `798f884bc3294b5a80731366aaefc99c9d622d47` |
| `.git/HEAD` | `ref: refs/heads/arena/02869c32-actual-new-clicker` |
| `origin/arena/02869c32-actual-new-clicker` | `798f884bc3294b5a80731366aaefc99c9d622d47` |
| `FETCH_HEAD` после `git fetch` | `798f884bc3294b5a80731366aaefc99c9d622d47` |
| GitHub API `branches/arena/02869c32-actual-new-clicker` | `sha = 798f884bc329…`, `protected = false` |
| `git status --short` до работы | чисто (без расхождений) |
| `git merge-base --is-ancestor d17af3e 798f884` | ДА; расстояние ровно **2 коммита** |

`d17af3e95352fbe26c9040fed9f1d5aed9314e97` от 2026-11-10 16:05 UTC —
`art(heroine-01): stage 05 E1 - contour masks and 20 RGBA layers`.
Именно он был HEAD **в начале этой сессии**, до публикации E2. В reflog это видно прямо:

```
04:38:06  clone: from …                -> 1068c68
04:38:07  checkout: …                  -> 371bd6a
04:38:27  reset: moving to d17af3e     -> d17af3e   ← состояние на старте сессии
05:28:17  commit: …publish candidates  -> 7f74ade
05:37:12  commit: …record selection    -> 798f884
```

**Наиболее вероятная причина расхождения:** в интерфейсе/контексте, который ты видишь,
сохранился **снимок состояния ветки на момент старта сессии** (тогда HEAD и правда был
`d17af3e`), а не живое значение git. Это не потеря коммитов и не откат: `7f74ade` и
`798f884` на месте, оба запушены, удалённая ветка указывает на `798f884`.
Дополнительно: `ORIG_HEAD` до сих пор `371bd6a` (от первого checkout), а `origin/HEAD`
указывает на `main` = `1068c68`; если панель показывает «базовый» коммит ветки, это тоже
может давать устаревшее значение. Я **не могу** однозначно утверждать, какой именно
источник выдал `d17af3e` в твоём интерфейсе, — это единственное, что лежит вне доступной
мне проверки; факты git и GitHub приведены выше и однозначны.

**Ничего не сбрасывал и не переписывал.** В этом ходе выполнен только `git fetch`
(обновление remote-tracking ref, который и до этого уже был `798f884`), а также чтение
`git log`, `reflog`, `show-ref`, `gh api`. Ни `reset`, ни `rebase`, ни `push --force`,
